# EXAM_05_04. Удаление повторов — теория

## 1. С чего начать

Нужно оставить каждое число только один раз — на месте его первого появления относительно других уникальных чисел.

Например:

```text
Вход:  1 2 1 3 1 4 -1
Вывод: 1 2 3 4
```

Повторы могут находиться не только рядом. Поэтому сравнения с предыдущим элементом недостаточно.

Сортировать последовательность тоже нельзя: сортировка может изменить требуемый порядок.

```text
Вход:  5 2 5 1 -1
Вывод: 5 2 1
```

Число `-1` обозначает конец и не входит в последовательность.

## 2. Нужно ли сначала сохранять все числа

Нет. Можно сразу сохранять только уникальные числа.

Для каждого прочитанного значения:

1. Проверить, есть ли оно в массиве.
2. Если есть — пропустить.
3. Если нет — добавить в конец.

Таким образом, мы не удаляем повторы из готового массива, а вообще не записываем их.

Добавление в конец сохраняет порядок первых появлений.

## 3. Как искать повтор

Используем флаг:

```c
int found = 0;
```

Его значения:

- `0` — совпадение пока не найдено;
- `1` — число уже есть в массиве.

Просматриваем сохранённые элементы:

```c
for (int i = 0; i < size; i++) {
    if (array[i] == value) {
        found = 1;
        break;
    }
}
```

`break` завершает ближайший цикл. После первого совпадения продолжать поиск не нужно.

Флаг создаётся заново для каждого прочитанного числа. Результат поиска предыдущего числа не должен влиять на следующий поиск.

## 4. Как расширять массив

Количество уникальных чисел заранее неизвестно, поэтому используем динамический массив:

```c
int *array = NULL;
int size = 0;
```

`size` — количество уже сохранённых элементов.

Для нового числа нужно место ещё под один `int`:

```c
int *temp = realloc(array, (size + 1) * sizeof(int));
```

- `size + 1` — новое количество элементов;
- `sizeof(int)` — размер одного элемента в байтах;
- произведение — требуемый размер блока памяти.

При первом добавлении `array` равно `NULL`. В таком случае `realloc` работает как `malloc`: выделяет новый блок.

При следующих добавлениях функция изменяет размер блока, сохраняя прежние элементы. Адрес блока при этом может измениться.

### Зачем нужен временный указатель

Не стоит сразу писать:

```c
array = realloc(array, new_size);
```

Если выделение ненулевого блока не удалось, `realloc` вернёт `NULL`, но старый блок останется выделенным. Прямое присваивание потеряет его адрес.

Поэтому сначала проверяем временный указатель:

```c
if (temp == NULL) {
    free(array);
    printf("n/a");
    return 0;
}
```

И только после успешной проверки обновляем `array`:

```c
array = temp;
array[size] = value;
size++;
```

До увеличения `size` эта переменная указывает на индекс новой свободной позиции.

## 5. Алгоритм решения

1. Создать пустой динамический массив.
2. Читать числа по одному до `-1`.
3. Если встретилось другое отрицательное число — освободить память и вывести `n/a`.
4. Для каждого допустимого числа:
  - поискать его среди сохранённых;
  - если оно уже есть — пропустить;
  - иначе расширить массив и добавить число.
5. Проверить, что чтение завершилось именно на `-1`.
6. Вывести сохранённые числа через пробел.
7. Освободить память.

## 6. Как проверить завершение ввода

Цикл:

```c
while (scanf("%d", &value) == 1 && value != -1)
```

может закончиться как после `-1`, так и из-за ошибки чтения.

Поэтому заранее задаём:

```c
int value = 0;
```

А после цикла проверяем:

```c
if (value != -1) {
    free(array);
    printf("n/a");
    return 0;
}
```

Начальный ноль позволяет безопасно выполнить проверку, даже если самое первое чтение не удалось.

### Пустая последовательность

Вход:

```text
-1
```

допустим по примеру из условия.

Массив остаётся пустым, цикл вывода не выполняется, и программа ничего не печатает.

Это отличается от пустого потока ввода: если данных вообще нет, признак конца `-1` не прочитан и программа выводит `n/a`.

> Разбор через `%d` предполагает, что числа помещаются в `int`. Он не проверяет весь текст после признака конца. Также этот простой вариант не содержит проверок переполнения счётчика и размера выделения памяти для чрезвычайно больших последовательностей.

## 7. Как вывести числа без лишнего пробела

Печатаем пробел перед каждым элементом, кроме первого:

```c
for (int i = 0; i < size; i++) {
    if (i > 0) {
        printf(" ");
    }

    printf("%d", array[i]);
}
```

Так между элементами будет ровно один пробел, а в начале и конце — ни одного.

Перенос строки не добавляем.

Вывод начинается только после успешного чтения последовательности. Иначе при поздней ошибке можно было бы получить смесь чисел и `n/a`.

## 8. Пошаговый разбор

Вход:

```text
5 2 5 0 2 7 -1
```

| Прочитано | Действие | Сохранённые элементы |
| --- | --- | --- |
| `5` | Массив пуст — добавляем | `5` |
| `2` | Такого числа нет — добавляем | `5 2` |
| `5` | Уже есть — пропускаем | `5 2` |
| `0` | Такого числа нет — добавляем | `5 2 0` |
| `2` | Уже есть — пропускаем | `5 2 0` |
| `7` | Такого числа нет — добавляем | `5 2 0 7` |
| `-1` | Завершаем чтение | `5 2 0 7` |

Результат:

```text
5 2 0 7
```

## 9. Скорость работы

Если все числа разные, для каждого нового числа приходится просматривать весь накопленный массив.

Для `n` входных элементов количество сравнений в худшем случае растёт как `n²`. Дополнительная память нужна только под уникальные элементы.

Это простой учебный алгоритм. Для очень больших последовательностей существуют более быстрые способы, но они требуют дополнительных структур данных.

## 10. Частые ошибки

| Ошибка | Почему это неправильно |
| --- | --- |
| Сравнивать только с предыдущим числом | Повторы могут находиться далеко друг от друга |
| Сортировать массив | Изменится порядок первых вхождений |
| Не сбрасывать `found` перед новым поиском | Результат предыдущего поиска повлияет на следующий |
| Добавлять число при первом несовпадении | Совпадение может находиться дальше в массиве |
| Сразу присваивать результат `realloc` в `array` | При ошибке можно потерять адрес выделенной памяти |
| Считать `-1` ошибкой пустой последовательности | По примеру пустая последовательность допустима |
| Не проверять наличие завершающего `-1` | Ошибка чтения может быть принята за нормальное завершение |
| Забыть `free(array)` при выходе | Выделенный блок не будет явно освобождён |
