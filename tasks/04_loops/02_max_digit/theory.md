# EXAM_04_02. Наибольшая цифра — теория

## 1. С чего начать

Нужно найти наибольшую цифру введённого целого числа.

Например:

```text
1824 → 8
```

Для этого будем выделять цифры по одной и сравнивать каждую с текущим максимумом.

Знак минус не является цифрой и не влияет на ответ:

```text
-1824 → 8
```

## 2. Как выделять цифры

Для положительного целого числа:

- `% 10` — получить последнюю цифру;
- `/ 10` — убрать последнюю цифру.

Например:

```text
1824 % 10 = 4
1824 / 10 = 182
```

Повторяем операции, пока число не станет равным нулю:

```text
1824 → 182 → 18 → 1 → 0
```

Цифры будут получены справа налево:

```text
4, 2, 8, 1
```

Для поиска максимума порядок цифр не важен.

## 3. Как запоминать наибольшую цифру

Все цифры находятся в диапазоне от `0` до `9`. Поэтому начальный максимум можно установить равным нулю:

```c
int max = 0;
```

Каждую выделенную цифру сравниваем с ним:

```c
if (digit > max) {
    max = digit;
}
```

Если цифра больше — обновляем максимум. Иначе ничего не меняем.

Хранить все цифры в массиве не нужно.

## 4. Как обработать отрицательное число

В C остаток от деления отрицательного числа на `10` может быть отрицательным:

```text
-123 % 10 = -3
```

Полученную цифру можно сделать положительной:

```c
int digit = n % 10;
if (digit < 0) {
    digit = -digit;
}
```

Затем продолжаем делить исходное число на `10`:

```text
-123 / 10 = -12
 -12 / 10 = -1
  -1 / 10 = 0
```

Целочисленное деление в современном C отбрасывает дробную часть в сторону нуля. Поэтому цикл завершится и для отрицательного числа.

### Почему не просто написать `n = -n`

У типа `int` диапазон отрицательных и положительных значений несимметричен.

Например, для обычного 32-битного `int`:

```text
Минимум: -2147483648
Максимум: 2147483647
```

Положительное число `2147483648` в такой `int` не помещается. Поэтому смена знака минимального значения вызывает переполнение знакового типа — неопределённое поведение.

Смена знака отдельного остатка безопасна: результат `n % 10` находится в диапазоне от `-9` до `9`.

## 5. Зачем нужен `do ... while`

У числа `0` тоже есть цифра — ноль. Её нужно обработать.

Обычный цикл:

```c
while (n != 0) {
    /* Обработка цифры. */
}
```

при исходном `n = 0` не выполнится ни разу.

Цикл `do ... while` сначала выполняет тело и только потом проверяет условие:

```c
do {
    /* Обработка цифры. */
} while (n != 0);
```

Поэтому он выполнится хотя бы один раз.

Для нуля получится:

```text
0 % 10 = 0
Максимум остаётся 0
0 / 10 = 0
Цикл завершается
```

В этой задаче при начальном `max = 0` обычный `while` тоже дал бы правильный ответ для нуля. Но `do ... while` явно обрабатывает его единственную цифру.

## 6. Алгоритм решения

1. Прочитать целое число.
2. Если чтение не удалось — вывести `n/a` и завершить программу.
3. Проверить, что после числа нет ничего, кроме пробельных символов — иначе вывести `n/a`.
4. Установить максимум равным `0`.
5. Выполнить хотя бы один раз:
  - получить остаток от деления числа на `10`;
  - если остаток отрицательный — сменить его знак;
  - сравнить цифру с максимумом и при необходимости обновить максимум;
  - разделить число на `10`, убрав последнюю цифру.
6. Повторять, пока число не станет равным нулю.
7. Вывести максимум без переноса строки.

## 7. Что понадобится из C

### Чтение и проверка

Для целого числа используем `int` и `%d`:

```c
if (scanf("%d", &n) != 1) {
    printf("n/a");
    return 0;
}
```

`&n` — адрес переменной, в которую записывается число.

`scanf` должна успешно прочитать одно значение и вернуть `1`. Если этого не произошло, выводим `n/a`.

> Такая проверка обнаруживает неудачное чтение, но не проверяет ввод целиком. Например, `123abc` может быть прочитано как `123`. Кроме того, чтение через `%d` предполагает, что число помещается в `int`: проверка возвращаемого значения не защищает от выхода за его диапазон.

### Почему одной проверки `scanf != 1` недостаточно

`scanf("%d", &n)` читает число ровно до первого символа, который не может быть его частью, и **останавливается**, не трогая всё, что идёт дальше. Он не смотрит, есть ли после числа что-то ещё.

Из-за этого такие входы проходят проверку `scanf != 1`, хотя по условию задачи должны давать `n/a`:

```text
"12abc" → scanf читает 12, буквы "abc" остаются непрочитанными → n/a ожидается, но n = 12
"1.5"   → scanf читает 1, символы ".5" остаются непрочитанными     → n/a ожидается, но n = 1
```

Программа при этом не падает и не возвращает ошибку — она просто использует `12` или `1`, как будто ввод был корректным числом. Отличить такой случай от честного `"12"` можно только одним способом: проверить, что осталось в потоке ввода **после** того, как `scanf` прочитал число.

Для этого дочитываем оставшиеся символы строки посимвольно через `getchar()` и проверяем, что среди них нет ничего, кроме пробела, табуляции, `\r` и завершающего `\n`:

```c
int c;
while ((c = getchar()) != EOF && c != '\n') {
    if (c != ' ' && c != '\t' && c != '\r') {
        printf("n/a");
        return 0;
    }
}
```

Если попался любой другой символ (буква, точка и т. п.) — значит, ввод был не просто числом, и нужно вывести `n/a`, даже если само число `scanf` прочитал успешно.

### Удаление последней цифры

```c
n /= 10;
```

Это сокращённая запись:

```c
n = n / 10;
```

Оба операнда целые, поэтому выполняется целочисленное деление.

### Условие продолжения

```c
while (n != 0);
```

Продолжаем, пока остались необработанные цифры.

Условие `n > 0` здесь не подходит: число может быть отрицательным.

Обрати внимание на точку с запятой после условия — она обязательна в конструкции `do ... while`.

### Вывод

```c
printf("%d", max);
```

Максимум хранится в `int`, поэтому используется `%d`.

Не добавляем перенос строки, пробелы и пояснения.

## 8. Пошаговый разбор

Вход:

```text
-1824
```

Начальный максимум — `0`.

| Число до деления | Остаток `% 10` | Цифра после обработки знака | Максимум |
| --- | --- | --- | --- |
| `-1824` | `-4` | `4` | `4` |
| `-182` | `-2` | `2` | `4` |
| `-18` | `-8` | `8` | `8` |
| `-1` | `-1` | `1` | `8` |

После последнего деления число становится равным нулю, и цикл завершается.

Результат:

```text
8
```

## 9. Частые ошибки

| Ошибка | Почему это неправильно |
| --- | --- |
| Не инициализировать `max` | Первое сравнение использует неопределённое значение |
| Забыть `n /= 10` | Ненулевое число не изменяется, цикл не заканчивается |
| Сравнивать отрицательный остаток с максимумом | Нужно сравнивать цифры от `0` до `9` |
| Использовать `n > 0` для продолжения цикла | Отрицательное число не будет полностью обработано |
| Менять знак всего числа через `n = -n` | Для минимального `int` возникает переполнение |
| Забыть `;` после `while` в `do ... while` | Это синтаксическая ошибка |
| Добавить `\n` | Условие запрещает перенос строки в конце ответа |
| Проверять только `scanf(...) != 1` | `"12abc"` и `"1.5"` успешно дают `n = 12` и `n = 1` — тест ждёт `n/a`, а программа выводит цифру |
