# EXAM_03_04. Число внутри отрезка — Тесты

## Компиляция

Все файлы решения собираются с жёсткими предупреждениями:

```bash
gcc -Wall -Wextra -Werror -std=c11 main.c -o main
```

## Валидные данные

| Вход          | Результат | Команда                        | Пояснение                       |
| ------------- | --------- | ------------------------------ | ------------------------------- |
| `0 9 4`       | `1`       | `echo "0 9 4" \| ./main`       | `4` строго между `0` и `9`      |
| `9 0 4`       | `1`       | `echo "9 0 4" \| ./main`       | порядок `A` и `B` не важен      |
| `10 20 15`    | `1`       | `echo "10 20 15" \| ./main`    | `15` строго между `10` и `20`   |
| `5 2 3`       | `1`       | `echo "5 2 3" \| ./main`       | `3` между `5` и `2`             |
| `0 1 4`       | `0`       | `echo "0 1 4" \| ./main`       | `4` вне отрезка `[0, 1]`        |
| `5 2 1`       | `0`       | `echo "5 2 1" \| ./main`       | `1` вне отрезка `[5, 2]`        |
| `0 0 0`       | `0`       | `echo "0 0 0" \| ./main`       | `C` совпадает с краями          |
| `1 5 1`       | `0`       | `echo "1 5 1" \| ./main`       | `C` совпадает с `A`             |
| `1 5 5`       | `0`       | `echo "1 5 5" \| ./main`       | `C` совпадает с `B`             |
| `100 200 50`  | `0`       | `echo "100 200 50" \| ./main`  | `50` ниже отрезка `[100, 200]`  |
| `100 200 300` | `0`       | `echo "100 200 300" \| ./main` | `300` выше отрезка `[100, 200]` |

## Некорректные данные (`n/a`)

| Вход     | Ожидаемый результат | Команда                   | Причина                            |
| -------- | ------------------- | ------------------------- | ---------------------------------- |
| `0 9`    | `n/a`               | `echo "0 9" \| ./main`    | слишком мало чисел                 |
| `a b c`  | `n/a`               | `echo "a b c" \| ./main`  | не являются числами                |
| `0 9 xx` | `n/a`               | `echo "0 9 xx" \| ./main` | третье значение не является числом |

> По условию `C` должен находиться **строго** между `A` и `B`, поэтому совпадение с одной из границ даёт `0`.

### Cppcheck

Статический анализ кода.

Нужен, чтобы найти потенциальные ошибки и подозрительные места в исходнике, которые компилятор может не заметить.

```bash
cppcheck --enable=all --suppress=missingIncludeSystem main.c
```

### Clang-format

Проверка стиля и форматирования кода.

```bash
clang-format -n -Werror main.c
```

Если нужно автоматически отформатировать файл:

```bash
clang-format -i main.c
```

### Valgrind

Проверка ошибок работы с памятью и утечек памяти.

Нужен для поиска проблем с памятью во время выполнения программы.

```bash
echo "0 9 4" | valgrind --leak-check=full ./main
```

> Обратите внимание: Valgrind запускается уже на скомпилированном файле.
