# EXAM_08_03. Студент с наивысшим баллом — теория

## 1. С чего начать

Задача проще, чем 08_01 и 08_02. Не нужно ни среднее считать, ни сортировать. Нужно просто найти одного студента с максимальной оценкой.

Шаги:
1. Прочитать N и данные студентов.
2. Пройти по массиву и запомнить индекс лучшего.
3. Вывести его.
4. Освободить память.

## 2. Поиск максимума

Классический алгоритм:

```c
int best = 0;
for (int i = 1; i < n; i++) {
    if (students[i].rate > students[best].rate) {
        best = i;
    }
}
```

- Начинаем с `best = 0` — первый студент пока «лучший».
- Сравниваем каждого следующего с текущим лучшим.
- Если нашли кого-то лучше — обновляем `best`.

### Почему `>`, а не `>=`

С `>=` при равных оценках `best` обновится на последнего. С `>` — останется первый. Условие требует первого, поэтому `>`.

### Почему не инициализировать `best_rate = -1`

Можно и так, но проще запоминать **индекс**, а не значение. Тогда не нужна отдельная переменная для максимального балла, и обращение к имени студента будет через `students[best].name`.

## 3. Ввод и память

Полностью аналогично заданиям 08_01 и 08_02:
- `scanf("%d", &n)` + съедание `'\n'`.
- `malloc` + проверка на `NULL`.
- Чтение имени через `getchar`.
- `free` в конце.

Подробности — в теории к 08_01.

## 4. Вывод

```c
printf("%s %d", students[best].name, students[best].rate);
```

Один студент, одна строка, без переноса в конце.

## 5. Сложность

Один проход по массиву — `O(n)`. Быстрее, чем сортировка (`O(n²)`), потому что нам не нужен порядок, а только один максимум.

## 6. Частые ошибки

| Ошибка | Почему |
| --- | --- |
| `>=` вместо `>` | Выведется последний из равных, а не первый |
| Начать цикл с `i = 0` | Лишнее сравнение, но не ошибка |
| Искать максимум до чтения всех данных | Нет данных для сравнения |
| Забыть `free` | Утечка |
