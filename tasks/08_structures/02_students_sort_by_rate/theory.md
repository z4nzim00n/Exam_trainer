# EXAM_08_02. Сортировка студентов по баллам — теория

## 1. С чего начать

Задача — прочитать N студентов, отсортировать их по убыванию оценки и вывести список.

Разбивается на четыре шага:
1. Прочитать данные (как в 08_01).
2. Отсортировать массив.
3. Вывести результат.
4. Освободить память.

Первый и четвёртый шаги — те же, что в задании 08_01. Новое здесь — **сортировка**.

## 2. Сортировка пузырьком

Простейший алгоритм сортировки. Идея: проходим по массиву и сравниваем соседние элементы. Если они «в неправильном порядке» — меняем местами. Повторяем, пока весь массив не станет отсортированным.

За один проход самый маленький элемент «всплывает» в конец массива, поэтому алгоритм и называется пузырьковым.

### Как это выглядит на примере

Массив оценок: `10, 20, 30`. Хотим по убыванию.

**Проход 1:**
- Сравниваем `10` и `20`. `10 < 20` — меняем: `20, 10, 30`.
- Сравниваем `10` и `30`. `10 < 30` — меняем: `20, 30, 10`.

После первого прохода наименьший (`10`) в конце.

**Проход 2:**
- Сравниваем `20` и `30`. `20 < 30` — меняем: `30, 20, 10`.
- `10` в конце уже не трогаем.

Массив отсортирован.

### Код

```c
for (int i = 0; i < n - 1; i++) {
    for (int j = 0; j < n - 1 - i; j++) {
        if (students[j].rate < students[j + 1].rate) {
            struct student tmp = students[j];
            students[j] = students[j + 1];
            students[j + 1] = tmp;
        }
    }
}
```

Разбор:
- `i` — номер прохода. После `i` проходов последние `i` элементов уже стоят на своих местах.
- `j < n - 1 - i` — не трогаем уже отсортированный «хвост».
- `students[j].rate < students[j + 1].rate` — если левый меньше правого, порядок неправильный (мы сортируем по убыванию).
- Обмен через временную переменную `tmp`.

### Почему `<`, а не `<=`

Если использовать `<=`, равные элементы будут меняться местами. Это нарушит **устойчивость**: студенты с одинаковой оценкой поменяют порядок относительно ввода.

С `<` сравнение равных — ложь, обмена нет, порядок сохраняется.

## 3. Обмен структур

```c
struct student tmp = students[j];
students[j] = students[j + 1];
students[j + 1] = tmp;
```

В C можно присваивать структуры целиком — все поля копируются автоматически. Ни цикла по полям, ни `memcpy` не нужно.

Обмен трёхшаговый:
1. Сохраняем левый в `tmp`.
2. Записываем правый на место левого.
3. Записываем `tmp` на место правого.

Порядок важен. Если сделать `students[j] = students[j+1]` первым без сохранения, левый элемент потеряется.

## 4. Вывод с переносами между элементами

Условие: **в конце не должно быть переноса строки**.

Простой цикл `printf("%s %d\n", ...)` добавит `\n` после каждого элемента, включая последний. Это ошибка.

Правильный подход — печатать `\n` **перед** каждым элементом, кроме первого:

```c
for (int i = 0; i < n; i++) {
    if (i > 0) {
        putchar('\n');
    }
    printf("%s %d", students[i].name, students[i].rate);
}
```

Логика:
- Первый элемент (i=0): без `\n` впереди.
- Все остальные: сначала `\n`, потом сам элемент.

В итоге переносы стоят **между** элементами, но не после последнего.

## 5. Сложность

Пузырьковая сортировка — `O(n²)`. Для N ≤ 100 это `10000` сравнений — мгновенно.

Для больших массивов лучше `qsort` из `<stdlib.h>` или другие алгоритмы. Но для этого задания пузырёк — самое подходящее по простоте и понятности.

## 6. Алгоритм целиком

1. Читаем N.
2. Съедаем `'\n'` после N.
3. Выделяем массив на N студентов.
4. В цикле N раз читаем имя и оценку.
5. Сортируем пузырьком по убыванию оценки.
6. Выводим студентов в формате `Имя Оценка`, разделяя переносами строк.
7. Освобождаем память.

## 7. Пошаговый разбор

Вход:
```
3
Anton
10
Sergey
20
Andrey
30
```

**После чтения:**
```
students[0] = {name: "Anton",  rate: 10}
students[1] = {name: "Sergey", rate: 20}
students[2] = {name: "Andrey", rate: 30}
```

**Сортировка (по убыванию):**

Проход 1 (i=0):
- j=0: `10 < 20` → меняем → `Sergey, Anton, Andrey`
- j=1: `10 < 30` → меняем → `Sergey, Andrey, Anton`

Проход 2 (i=1):
- j=0: `20 < 30` → меняем → `Andrey, Sergey, Anton`

Готово.

**Вывод:**
```
Andrey 30
Sergey 20
Anton 10
```

## 8. Особые случаи

### Один студент

Циклы сортировки не выполняются (`n - 1 == 0`). Выводится сам студент.

### Уже отсортированный массив

Пузырёк всё равно делает все проходы, обменов не происходит. Результат правильный.

### Одинаковые оценки

Благодаря `<` (а не `<=`), порядок сохраняется. Например, если Alice и Carol обе с оценкой 75, а Alice введена раньше — она останется выше Carol в выводе.

## 9. Частые ошибки

| Ошибка | Почему это неправильно |
| --- | --- |
| Использовать `<=` в сравнении | Ломает устойчивость сортировки |
| Печатать `\n` после каждого элемента | В конце появится лишний перенос |
| Забыть сохранить `tmp` при обмене | Один из элементов потеряется |
| Сортировать по возрастанию | Условие требует по убыванию |
| Забыть про имена с пробелами | `scanf("%s", ...)` не подходит |
| Забыть съесть `'\n'` после чисел | Следующее имя прочитается пустым |
| Забыть `free` | Утечка памяти |
