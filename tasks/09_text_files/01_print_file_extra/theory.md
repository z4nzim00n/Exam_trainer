# EXAM_09_01. Вывод файла — теория

## 1. Что нужно сделать

Программа получает на `stdin` путь к файлу, открывает его и выводит содержимое на `stdout` **байт в байт**: без лишних пробелов, переносов и пояснений. Если открыть файл не удалось — вывести `n/a`.

```text
f2.txt  →  Hello
           World
nofile.txt → n/a
```

## 2. Как читать путь

Путь — одно слово без пробелов, поэтому хватит `scanf`:

```c
char path[256];

if (scanf("%255s", path) != 1) {
    printf("n/a");
    return 0;
}
```

- `%255s` ограничивает длину, чтобы не выйти за пределы массива на 256 байт;
- имя массива `path` уже является адресом первого элемента, поэтому `&` не нужен;
- `scanf` возвращает число успешно прочитанных значений; при пустом вводе будет `EOF`, а не `1`.

## 3. Открытие файла

```c
FILE* file = fopen(path, "r");
if (file == NULL) {
    printf("n/a");
    return 0;
}
```

`fopen` возвращает указатель на `FILE` или `NULL`, если файл не существует, нет прав на чтение и т. п. Проверять результат обязательно: разыменование `NULL` приведёт к падению.

Режим `"r"` открывает файл только для чтения. `"r+"` тоже открыл бы существующий файл, но разрешил бы запись — здесь она не нужна.

## 4. Чтение и вывод

Файл удобно читать по одному символу:

```c
int c;

while ((c = fgetc(file)) != EOF) {
    putchar(c);
}
```

- `fgetc` возвращает код следующего байта или `EOF`, когда файл закончился;
- результат хранится в `int`, а не в `char`: `EOF` — отрицательное значение, которое не обязано помещаться в `char`;
- `putchar(c)` выводит один символ в `stdout`.

Такой цикл не добавляет ничего от себя: что было в файле, то и попадёт в вывод, включая все переводы строк и пробелы.

### Почему не `printf("%s", ...)`

Для `printf("%s")` нужен массив с завершающим `'\0'`. Файл может быть больше любого буфера или содержать нулевые байты. Посимвольное чтение не требует буфера и работает с файлом любого размера.

## 5. Закрытие файла

```c
fclose(file);
```

Файл нужно закрыть на всех путях, где он был успешно открыт. Закрытие освобождает ресурсы; при чтении оно ещё и завершает работу с потоком. Valgrind показывает незакрытый файл как утечку.

Если `fopen` вернул `NULL`, закрывать нечего — `fclose(NULL)` нельзя.

## 6. Полная программа

```c
#include <stdio.h>

int main(void) {
    char path[256];

    if (scanf("%255s", path) != 1) {
        printf("n/a");
        return 0;
    }

    FILE* file = fopen(path, "r");
    if (file == NULL) {
        printf("n/a");
        return 0;
    }

    int c;
    while ((c = fgetc(file)) != EOF) {
        putchar(c);
    }

    fclose(file);

    return 0;
}
```

## 7. Порядок действий

1. Прочитать путь, проверить результат `scanf`.
2. Открыть файл в режиме `"r"`, проверить `NULL`.
3. В цикле читать символы через `fgetc`, пока не вернётся `EOF`.
4. Каждый символ выводить через `putchar`.
5. Закрыть файл через `fclose`.

## 8. Особые случаи

| Случай | Поведение |
| --- | --- |
| файл содержит `Hello\nWorld` | вывод будет ровно `Hello\nWorld` |
| пустой файл | цикл не выполнится, вывод пустой |
| файла нет | `fopen` вернул `NULL` → `n/a` |
| путь не введён | `scanf` вернул `EOF` → `n/a` |
| в файле есть пробелы и знаки | они выводятся без изменений |

## 9. Частые ошибки

| Ошибка | Почему это неправильно |
| --- | --- |
| Не проверить `fopen` на `NULL` | Программа упадёт при обращении к несуществующему файлу |
| Открыть файл в режиме `"w"` | Файл будет очищен вместо чтения |
| Использовать `char c` для `fgetc` | `EOF` может не поместиться в `char`, цикл зациклится |
| Добавлять `\n` после каждого символа | Испортит содержимое файла |
| Выводить `n/a` с переводом строки | Формат ответа задан условием |
| Не закрыть файл | Утечка ресурсов, Valgrind покажет ошибку |
| Читать через `fscanf("%s")` | Будут прочитаны только слова без пробелов и переводов строк |
