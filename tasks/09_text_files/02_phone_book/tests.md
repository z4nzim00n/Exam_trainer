# EXAM_09_02. Телефонный справочник — Тесты

## Компиляция

```
gcc -Wall -Wextra -Werror -std=c11 main.c -o main
```

## Подготовка тестовых файлов

Файлы создаются в папке с программой командой `printf`. Символ `\n` внутри `printf` означает перевод строки.

```
printf 'Smith:8-950-111-22-33\nMiller:8-900-999-66-55' > t1.txt
printf 'Test:8-950-111-22-33\n' > t2.txt
printf 'A:8-000-000-00-00\nB:8-111-111-11-11\nC:8-222-222-22-22\n' > t3.txt
```

## Валидные данные

| Ввод (stdin) | Содержимое файла | Результат | Команда | Пояснение |
|---|---|---|---|---|
| `t1.txt` | `Smith:8-950-111-22-33`<br>`Miller:8-900-999-66-55` | `Smith +7(950)111-22-33`<br>`Miller +7(900)999-66-55` | `echo "t1.txt" \| ./main` | пример из условия |
| `t2.txt` | `Test:8-950-111-22-33` и `\n` в конце файла | `Test +7(950)111-22-33` | `echo "t2.txt" \| ./main` | один контакт, `\n` в конце файла не даёт лишней строки |
| `t3.txt` | три контакта, `\n` в конце файла | `A +7(000)000-00-00`<br>`B +7(111)111-11-11`<br>`C +7(222)222-22-22` | `echo "t3.txt" \| ./main` | в конце вывода нет `\n` |

## Некорректные данные (n/a)

Файлы для проверок:

```
printf 'Smith:7-950-111-22-33' > e1.txt
printf 'Smith:8-950-11-122-33' > e2.txt
printf 'Smith:8-950-111-22-3a' > e3.txt
printf 'Smith8-950-111-22-33' > e4.txt
printf ':8-950-111-22-33' > e5.txt
printf 'Smith:8-950-111-22-333' > e6.txt
printf 'Smith:8-950-111-22-33\nBad:12345' > e7.txt
printf 'A:8-950-111-22-33\n\nB:8-900-999-66-55' > e8.txt
printf '' > e9.txt
printf 'Smith:8-950-111-22-33 ' > e10.txt
```

| Ввод (stdin) | Ожидаемый результат | Команда | Причина |
|---|---|---|---|
| `e1.txt` | `n/a` | `echo "e1.txt" \| ./main` | телефон начинается не с 8 |
| `e2.txt` | `n/a` | `echo "e2.txt" \| ./main` | дефисы стоят не на своих местах |
| `e3.txt` | `n/a` | `echo "e3.txt" \| ./main` | в телефоне буква вместо цифры |
| `e4.txt` | `n/a` | `echo "e4.txt" \| ./main` | нет двоеточия |
| `e5.txt` | `n/a` | `echo "e5.txt" \| ./main` | пустое имя |
| `e6.txt` | `n/a` | `echo "e6.txt" \| ./main` | в телефоне лишняя цифра |
| `e7.txt` | `n/a` | `echo "e7.txt" \| ./main` | первая строка верная, вторая плохая: выводится только `n/a`, первый контакт не печатается |
| `e8.txt` | `n/a` | `echo "e8.txt" \| ./main` | пустая строка внутри файла |
| `e9.txt` | `n/a` | `echo "e9.txt" \| ./main` | пустой файл |
| `e10.txt` | `n/a` | `echo "e10.txt" \| ./main` | лишний пробел в конце телефона |
| `nofile.txt` | `n/a` | `echo "nofile.txt" \| ./main` | такого файла нет |
| (пусто) | `n/a` | `./main < /dev/null` | путь не задан |

## Cppcheck

Статический анализ кода. Нужен, чтобы найти потенциальные ошибки и подозрительные места в исходнике, которые компилятор может не заметить.

```
cppcheck --enable=all --suppress=missingIncludeSystem main.c
```

## Clang-format

Проверка стиля и форматирования кода.

```
clang-format -n -Werror main.c
```

Если нужно автоматически отформатировать файл:

```
clang-format -i main.c
```

## Valgrind

Проверка ошибок работы с памятью и утечек памяти. Здесь это особенно важно: незакрытый файл (`fopen` без `fclose`) будет показан как утечка.

```
echo "t1.txt" | valgrind --leak-check=full ./main
```

Обратите внимание: Valgrind запускается уже на скомпилированном файле.
