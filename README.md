# Тренажёр по C

42 задания для подготовки к экзамену по C в Школе 21: от исправления ошибок в маленьких программах до строк, динамических массивов и матриц.

Внутри — условия, теория, решения и тесты. Можно идти по порядку или выбрать тему, которую хочется подтянуть.

Это не официальный список экзаменационных заданий. Цель — разобраться в основных приёмах и научиться писать небольшие программы самостоятельно.

### Что означает `_extra`

Папки с суффиксом `_extra`, например `06_count_words_extra`, содержат дополнительные тренировочные задания.

Они составлены для практики и не являются подтверждёнными. То есть их может не быть на экзамене, либо они будут, но
не в таком виде как здесь. 

## Как устроено задание

| Файл | Что в нём |
| --- | --- |
| `README.md` | Условие, ограничения и примеры |
| `main.c` | Место для твоего решения |
| `theory.md` | Объяснение алгоритма и необходимых конструкций C |
| `tests.md` | Тесты с ожидаемыми ответами и командами запуска |
| `solution.c` | Эталонное решение |
| `solution_commented.c` | То же решение с комментариями |

В первых двух разделах тесты и комментированные решения пока есть не у всех заданий.

## Как заниматься

1. Открой условие выбранного задания.
2. Попробуй написать решение в `main.c`.
3. Если застрял — загляни в `theory.md`.
4. Скомпилируй программу и проверь её на примерах и тестах.
5. Сравни свою реализацию с эталоном.

В заданиях на исправление ошибок сначала перенеси код из условия в `main.c`.

Твоё решение не обязано совпадать с эталоном. Главное — правильный результат и соблюдение ограничений.

## Случайный набор заданий

Открой `trainer.html` из локальной копии проекта в Chrome или Edge.

1. Выбери корень проекта — папку, содержащую `tasks`.
2. Разреши доступ к файлам.
3. Нажми «Новый набор».
4. Открой созданные файлы в `Your_tasks` и решай задания.

Тренажёр выбирает по одному заданию трёх уровней сложности.
Каждое можно заменить отдельно. Старые рабочие файлы не удаляются.

В рабочую папку копируется условие и создаётся пустой `main.c`.
Решения и теория остаются в исходных папках.

Это тренировочный формат, а не точная копия экзамена.

## Компиляция и запуск

Нужен компилятор GCC. Команды ниже рассчитаны на терминал Linux или WSL.

Перейди в папку задания и собери свою программу:

```bash
gcc -Wall -Wextra -Werror -std=c11 main.c -o main
```

Запусти:

```bash
./main
```

Входные данные можно передать сразу. Например, для проверки палиндрома:

```bash
printf 'level\n' | ./main
```

Чтобы проверить эталон, собери его отдельно:

```bash
gcc -Wall -Wextra -Werror -std=c11 solution.c -o reference
printf 'level\n' | ./reference
```

**Не собирай все `.c`-файлы через `*.c`:** каждый файл решения содержит отдельную программу со своей функцией `main`.

Если используются математические функции вроде `round`, может потребоваться `-lm`:

```bash
gcc -Wall -Wextra -Werror -std=c11 main.c -o main -lm
```

## Проверка решения

Обращай внимание на пробелы и переносы строк: правильное число с неправильным оформлением — тоже ошибка.

Если приглашение терминала появляется сразу после ответа, это нормально для заданий без завершающего `\n`.

Дополнительные инструменты устанавливаются отдельно.

**Проверка стиля** по `.clang-format` из корня проекта:

```bash
clang-format -n -Werror main.c
```

**Статический анализ:**

```bash
cppcheck --enable=all --suppress=missingIncludeSystem main.c
```

**Проверка памяти:**

```bash
gcc -Wall -Wextra -Werror -std=c11 -g main.c -o main
valgrind --leak-check=full --track-origins=yes ./main
```

После запуска введи данные выбранного задания. Примеры команд и граничные случаи находятся в его `tests.md`.
